# EventMatch — умный подбор event-подрядчиков

Мобильное приложение на React Native для подбора подрядчиков на мероприятия в Казахстане. Проект создан для задачи HackAlem «Умный подбор подрядчиков (#79-lite)».

Пользователь указывает город, дату, тип мероприятия, категорию и бюджет. Сервис выбирает до трёх подрядчиков из исходного каталога и объясняет, почему каждый подходит. Дополнительно можно задать язык и длительность мероприятия.

## Возможности

- Подбор по городу, категории, бюджету, формату, языку и длительности.
- Проверка занятости на конкретную дату, в том числе у площадок.
- До трёх карточек с ценой «от» и объяснением на основе данных профиля.
- Разные ответы для отсутствующей категории и отсутствия подходящих кандидатов.
- Пояснение причин, если результатов меньше трёх.
- Одинаковый порядок результатов при повторении запроса на неизменных данных.
- Передача флагов синтетических профилей и восстановленных данных в API.

## Технологии и архитектура

| Часть | Реализация |
|---|---|
| Мобильный интерфейс | React Native |
| Бэкенд | Node.js 22+, JavaScript, встроенный HTTP-сервер |
| API | HTTP / JSON |
| Источник данных | `src/data/contractors.json`, 66 профилей |
| Подбор | Жёсткие фильтры и детерминированное ранжирование |
| Объяснения | Поля профиля и фрагменты исходного описания |
| Тесты бэкенда | Встроенный `node:test` |

Мобильное приложение отправляет параметры в `POST /recommendations`. Сервер проверяет запрос, фильтрует каталог, ранжирует подходящие профили и возвращает карточки с объяснениями. Каталог загружается в память при старте сервера; после изменения JSON сервер нужно перезапустить.

**В текущем бэкенде нет внешнего LLM API или обученной модели.** Релевантность описания определяется лексически, а объяснения формируются программно. Приложение не выполняет бронирование, оплату или отправку заявок подрядчикам.

## Данные

Каталог содержит 66 анонимизированных профилей. Среди городов указаны Алматы, Астана и «Зарубежье». Период календаря занятости: **23 сентября — 31 декабря 2026 года**.

| Поле | Значение |
|---|---|
| `id`, `anon_name` | Идентификатор и анонимизированное имя |
| `categories`, `city` | Категории услуг и город |
| `price_from_kzt` | Начальная цена за мероприятие в тенге |
| `event_formats`, `languages` | Поддерживаемые форматы и языки |
| `max_hours` | Лимит часов; `null` — услуга не привязана к присутствию |
| `busy_dates` | Занятые даты |
| `description` | Исходное описание профиля |
| `synthetic` | Синтетический профиль |
| `city_imputed`, `price_imputed` | Город или цена заполнены при подготовке данных |

Списки в исходном JSON могут быть строками с разделителем `|`; сервер нормализует их в массивы. Флаги преобразуются в boolean. Подрядчики не добавляются при поиске, а отсутствующие факты не генерируются.

## Запуск бэкенда

Требуется Node.js 22 или новее. Из корня проекта:

```bash
cd backend
npm start
```

У бэкенда нет внешних npm-зависимостей, поэтому `npm install` в этой папке не требуется. Сервер запускается на порту 3000.

Проверка: откройте `http://localhost:3000/health` на компьютере. Ожидаемый ответ:

```json
{"status":"ok","contractor_count":66}
```

Для автоматического перезапуска при редактировании кода:

```bash
npm run dev
```

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/recommendations` | Подбор подрядчиков в заданном формате |
| GET | `/health` | Проверка доступности сервера |
| GET | `/catalog` | Города, категории, форматы, языки, период календаря |
| OPTIONS | каждый из этих путей | CORS preflight для web-версии |

`POST /recommendations`, `Content-Type: application/json`:

```json
{
  "city": "Алматы",
  "date": "2026-10-17",
  "event_type": "корпоратив",
  "category": "Ведущий",
  "budget": 800000,
  "duration_hours": null,
  "language": null
}
```

Поля `duration_hours`, `language` можно не передавать или передать null. Числа должны быть числами JSON, не строками. Дата — локальная календарная дата YYYY-MM-DD, не ISO timestamp. Категория, город, язык и формат сравниваются без учёта регистра и лишних пробелов; варианты значений берите из `/catalog`. Неизвестные поля вызывают 400, чтобы ошибки названий не отключали фильтры незаметно.

Для именно этого запроса реальные данные дают:

```json
{
  "status": "no_matches",
  "message": "Ни один из 10 подрядчиков не прошёл условия: заняты на выбранную дату: 5; цена выше бюджета: 5. Причины подсчитаны по первому непройденному условию.",
  "recommendations": []
}
```

Измените только дату на `2026-10-19` — будет одна карточка Ани Форджер с `status: "matched"`. Фактические ответы и другие демо сохранены в `backend/examples/demo-results.json`.

Карточка содержит ровно `id`, `anon_name`, `categories` (массив), `city`, `price_from_kzt` (число), `explanation`, `synthetic`, `city_imputed`, `price_imputed` (boolean). Верхний уровень: `status`, `message`, `recommendations`.

| HTTP | status | Значение |
|---|---|---|
| 200 | matched | Найдено от 1 до 3 |
| 200 | no_category_in_city | В городе нет этой категории |
| 200 | no_matches | Категория есть, но условия не проходят |
| 400 | invalid_request | Неверный JSON, поля, типы или дата |
| 422 | date_out_of_range | Дата вне 23.09.2026–31.12.2026; занятость неизвестна |
| 413 | payload_too_large | Запрос больше 16 КБ |
| 415 | unsupported_media_type | Не application/json |
| 408 | request_timeout | Тело запроса не получено за 5 секунд |
| 404 / 405 | not_found / method_not_allowed | Неверный путь / метод |
| 500 | internal_error | Непредвиденная ошибка |

При ошибках API тоже возвращает `status`, `message`, `recommendations: []`. Отсутствие подходящих подрядчиков не является HTTP-ошибкой.

## Правила подбора

1. Сначала совпадение города и категории строго внутри каталога.
2. Исключение по первому проваленному условию: дата → бюджет → формат → язык → длительность. Для залов используются те же busy_dates.
3. `max_hours: null` по определению датасета означает услугу без привязки ко времени присутствия, поэтому длительность её не исключает.
4. Оценка: бюджет 30/27/24 балла при цене до 70%/85%/100% бюджета; формат 25; заданный язык 15; заданная длительность 15; упоминание формата в описании 15. При нулевом бюджете допускается только нулевая цена. Описание проверяется по явным корням слов, это лексический сигнал, не embedding/LLM и не полноценное понимание смысла.
5. Порядок: score по убыванию → цена по возрастанию → id по возрастанию. Случайности нет.
6. Объяснение содержит цену, дату, формат, заданные дополнительные условия, флаги и индивидуальный фрагмент описания. Цитата берётся из данных, без приписывания опыта и гарантий.
7. Календарь ограничен периодом исходного датасета. За пределами окна возвращается 422, а не ложная доступность.

## Демонстрация

Сценарии проверены на приложенном каталоге. Во всех строках язык и длительность — `null`.

| Сценарий | Город | Дата | Формат | Категория | Бюджет, ₸ | Результат |
|---|---|---|---|---|---:|---|
| Плотная категория | Алматы | 2026-10-01 | корпоратив | Ведущий | 2 000 000 | 3 карточки |
| Редкая категория | Алматы | 2026-10-04 | свадьба | Флорист | 2 000 000 | 2 карточки |
| Все исключены | Алматы | 2026-10-17 | корпоратив | Ведущий | 800 000 | `no_matches` |
| Изменена только дата | Алматы | 2026-10-19 | корпоратив | Ведущий | 800 000 | 1 карточка: Аня Форджер |
| Нет категории в городе | Атырау | 2026-10-17 | корпоратив | Ведущий | 800 000 | `no_category_in_city` |

В редкой категории показан синтетический профиль; его флаг необходимо отображать на демо. Сравнение 17 и 19 октября демонстрирует влияние календаря. Повторение одного запроса должно сохранять порядок карточек.

Для проверки API без мобильного приложения можно выполнить в PowerShell:

```powershell
$body = @{
  city = 'Алматы'
  date = '2026-10-19'
  event_type = 'корпоратив'
  category = 'Ведущий'
  budget = 800000
  duration_hours = $null
  language = $null
} | ConvertTo-Json

Invoke-RestMethod -Uri 'http://localhost:3000/recommendations' `
  -Method Post `
  -ContentType 'application/json; charset=utf-8' `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

## Тестирование

Из корня проекта:

```bash
cd backend
npm test
```

Пять групп автоматических тестов бэкенда проверяют:

- Условия подбора и детерминизм на 100 днях исходного календаря.
- Смена даты, разные пустые исходы и контракт ответа.
- Занятость площадок, бюджет, язык, длительность и `max_hours: null`.
- Валидация типов, дат и диапазона календаря.
- HTTP-маршруты, CORS, ошибки JSON, тип содержимого и лимит тела запроса.

При подготовке бэкенда все пять групп прошли на исходных 66 профилях. Тесты бэкенда не заменяют проверку полного сценария на телефоне: заполнение формы, отправка запроса, показ карточек, пустых результатов и ошибок сети.

## Ограничения

- Данные и календарь статические; актуальность доступности определяется исходным датасетом.
- Даты за пределами окна календаря возвращают 422.
- Цена «от» используется для предварительного отбора, не гарантирует окончательную стоимость и не умножается на часы.
- Подбор не расширяет исходный каталог.
- Авторизация, бронирование, оплата и уведомления не входят в MVP.
- Объяснения формируются без LLM; лексическая релевантность описания не равнозначна семантической модели.

## Дальнейшее развитие

Возможные следующие этапы: синхронизация календарей, обновление цен, семантическое ранжирование описаний и LLM-формулировки на основе уже проверенных фактов. Эти возможности не входят в текущую реализацию.
