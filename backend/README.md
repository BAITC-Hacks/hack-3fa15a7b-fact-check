# EventMatch backend

Готовый HTTP-бэкенд на Node.js 22+ без npm-зависимостей. До 3 рекомендаций из существующего каталога; новые подрядчики не добавляются. Внешний AI API не подключён: объяснения детерминированы и основаны на полях и цитатах датасета. Это MVP для хакатона, не сервис бронирования.

## Первый шаг: расположение и запуск

Структура объединённого репозитория:

```text
backend/
  src/data/contractors.json
  src/services/             ← сервисы из исходных веток
  package.json
  server.js
  recommendations.js
frontend/
```

В терминале из корня вашего проекта:

```bash
cd backend
npm start
```

`npm install` не нужен. Откройте на компьютере http://localhost:3000/health — ожидается `{"status":"ok","contractor_count":66}`. Если порт занят, задайте PORT. Сервер читает JSON при запуске, после изменения данных перезапустите его.

Другой путь к данным можно указать в Windows PowerShell:

```powershell
$env:DATA_PATH = 'C:\полный\путь\contractors.json'
npm start
```

Сервисы участников сохранены в `backend/src/services/`. HTTP-сервер использует `recommendations.js` и общий JSON в `backend/src/data/contractors.json`. Frontend обращается к API через `frontend/src/services/api.js`.

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/recommendations` | Подбор подрядчиков в заданном формате |
| GET | `/health` | Проверка доступности сервера |
| GET | `/catalog` | Города, категории, форматы, языки, период календаря |
| OPTIONS | каждый из этих путей | CORS preflight для web-версии |

`POST /recommendations`, `Content-Type: application/json`:

```json
{
  "city": "Алматы",
  "date": "2026-10-17",
  "event_type": "корпоратив",
  "category": "Ведущий",
  "budget": 800000,
  "duration_hours": null,
  "language": null
}
```

Поля `duration_hours`, `language` можно не передавать или передать null. Числа должны быть числами JSON, не строками. Дата — локальная календарная дата YYYY-MM-DD, не ISO timestamp. Категория, город, язык и формат сравниваются без учёта регистра и лишних пробелов; варианты значений берите из `/catalog`. Неизвестные поля вызывают 400, чтобы ошибки названий не отключали фильтры незаметно.

Для именно этого запроса реальные данные дают:

```json
{
  "status": "no_matches",
  "message": "Ни один из 10 подрядчиков не прошёл условия: заняты на выбранную дату: 5; цена выше бюджета: 5. Причины подсчитаны по первому непройденному условию.",
  "recommendations": []
}
```

Измените только дату на `2026-10-19` — будет одна карточка Ани Форджер с `status: "matched"`. Для проверки используйте этот запрос через HTTP API.

Карточка содержит ровно `id`, `anon_name`, `categories` (массив), `city`, `price_from_kzt` (число), `explanation`, `synthetic`, `city_imputed`, `price_imputed` (boolean). Верхний уровень: `status`, `message`, `recommendations`.

| HTTP | status | Значение |
|---|---|---|
| 200 | matched | Найдено от 1 до 3 |
| 200 | no_category_in_city | В городе нет этой категории |
| 200 | no_matches | Категория есть, но условия не проходят |
| 400 | invalid_request | Неверный JSON, поля, типы или дата |
| 422 | date_out_of_range | Дата вне 23.09.2026–31.12.2026; занятость неизвестна |
| 413 | payload_too_large | Запрос больше 16 КБ |
| 415 | unsupported_media_type | Не application/json |
| 408 | request_timeout | Тело запроса не получено за 5 секунд |
| 404 / 405 | not_found / method_not_allowed | Неверный путь / метод |
| 500 | internal_error | Непредвиденная ошибка |

При ошибках API тоже возвращает `status`, `message`, `recommendations: []`. Отсутствие подходящих подрядчиков не является HTTP-ошибкой.

## Подключение React Native

Адаптер находится в `frontend/src/services/api.js`. Задайте `EXPO_PUBLIC_API_URL` в `frontend/.env`:

- Физический телефон: `http://IP_ВАШЕГО_КОМПЬЮТЕРА:3000`; IP виден в `ipconfig` на Windows. Телефон и компьютер должны быть в одной Wi-Fi сети. Разрешите Node.js в брандмауэре для частной сети.
- Android Emulator: `http://10.0.2.2:3000`.
- iOS Simulator на Mac: `http://localhost:3000`.

`localhost` на физическом телефоне указывает на телефон. Сервер слушает `0.0.0.0`, чтобы принимать запросы по Wi-Fi. Для HTTPS-релиза нужен отдельно развёрнутый сервер и HTTPS URL; размещение в интернете здесь не выполнялось. Если нативная debug-сборка блокирует локальный HTTP, разрешение cleartext/ATS должно быть ограничено средой разработки.

Пример вызова:

```js
const result = await fetchRecommendations({
  city: 'Алматы',
  date: '2026-10-19',
  event_type: 'корпоратив',
  category: 'Ведущий',
  budget: 800000,
  duration_hours: null,
  language: null,
});
setRecommendations(result.recommendations);
setMessage(result.message);
```

Обработайте исключение fetch на экране. Для двух пустых статусов покажите `message`, а для matched — карточки и `message`, особенно если их меньше трёх. Показывайте флаги синтетического профиля и восстановленных города/цены. `price_from_kzt` — цена ОТ за мероприятие, она не умножается на часы и не гарантирует итоговую стоимость.

## Правила подбора

1. Сначала совпадение города и категории строго внутри каталога.
2. Исключение по первому проваленному условию: дата → бюджет → формат → язык → длительность. Для залов используются те же busy_dates.
3. `max_hours: null` по определению датасета означает услугу без привязки ко времени присутствия, поэтому длительность её не исключает.
4. Оценка: бюджет 30/27/24 балла при цене до 70%/85%/100% бюджета; формат 25; заданный язык 15; заданная длительность 15; упоминание формата в описании 15. При нулевом бюджете допускается только нулевая цена. Описание проверяется по явным корням слов, это лексический сигнал, не embedding/LLM и не полноценное понимание смысла.
5. Порядок: score по убыванию → цена по возрастанию → id по возрастанию. Случайности нет.
6. Объяснение содержит цену, дату, формат, заданные дополнительные условия, флаги и индивидуальный фрагмент описания. Цитата берётся из данных, без приписывания опыта и гарантий.
7. Календарь ограничен периодом исходного датасета. За пределами окна возвращается 422, а не ложная доступность.

## Проверка

```bash
npm test
```

Интеграционные проверки: загрузка общего датасета, HTTP health, три исхода подбора и детерминизм. См. `test/integration.test.js`.

Переменные окружения: `PORT` (3000), `HOST` (0.0.0.0), `DATA_PATH`, `CORS_ORIGIN` (* для локального демо). Это публичное read-only API без авторизации и бронирования; постоянного изменения данных нет.
